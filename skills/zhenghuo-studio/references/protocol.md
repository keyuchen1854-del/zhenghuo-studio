# 整活片场：技能协作协议

版本：0.1.0。独立工具箱；已有项目的制作、授权和交付规则继续适用。

## 一条任务只维护一份项目记录

每个技能接收上一阶段的明确产物，提交自己的新增内容；不得重写别人的事实、已确认选择或验收结论。长资料存文件，交接只传路径、版本、摘要和必要内容。模型必须实际读取本步骤需要的正文，不能把路径或摘要当作已读全部。

项目记录的最少字段：

| 对象 | 必需内容 | 唯一负责方 |
|---|---|---|
| brief | 项目编号、目标、受众、市场、口播语言、字幕语言、时长、画幅、数量、路线、禁改项、确认状态 | 总导演根据用户要求维护 |
| facts | 商品事实编号、描述、证据位置、已核实／用户提供／未知；商品结构、颜色、件数、使用状态 | 总导演归集，任何技能均可提出勘误 |
| sources | 参考编号、素材路径、真实时长、时间基准、原口播、切点、可见事实、未知项 | 参考拆解模块 |
| concept | 选择的创意、叙事顺序、各参考只借鉴什么、商品展示理由、未选备选 | 总导演确认选案；创意模块提供候选 |
| dialogue | 源语、目标语、中文核对、逐句时间、实际配音长度或未测标记 | 翻译模块维护语言，编导维护叙事意图 |
| storyboard | 镜头编号、时间段、动作起终点、场景／人物／商品版本、台词编号、音效、字幕、连续性 | 故事板模块 |
| assets | 素材编号、文件、哈希、用途、来源、允许上传范围、验收状态 | 关键帧／宫格模块 |
| generation | 服务商和实际模型、请求参数、输入哈希、单价依据、批次预算、批准记录、任务编号、结果 | 生成适配器 |
| qa | 对应产物版本、检查者、商品／动作／语言／连续性问题时间点、通过／返修／未检查 | 审看流程，不让生成器自行宣称通过 |
| publish_copy | 对应成片版本、标题、文案、CTA、标签依据、中文核对 | 文案模块 |

每份阶段产物额外带：`artifact_id`、`schema_version`、`revision`、`depends_on`（父产物编号与版本）、`status`、`unresolved`。不能只靠文件名判断是否仍有效。

## 不相互抢工作的规则

1. 源素材层只记录发生了什么；改编层记录准备创作什么。观察、推断和新创意分别保存。原片口播不得被改写后冒充转写。
2. 商品事实、用户禁改项、已选路线、目标语言由项目记录统一提供。模块发现冲突时提交问题和建议，不静默修改。
3. 各参考先独立拆解。跨参考组合在创意层完成，不能把不同原片的时间线拼成一条“真实分镜”。
4. 概念与镜头时间属于故事层；模型时长与输入槽位属于执行层。生成适配器无法满足时返回可行拆段方案，不能自行删剧情、改台词或换模型。
5. 口播只维护一份带版本的目标语言正文。风格模块提出改写建议，经确认后更新这一份；后续图像、视频、字幕、文案引用对应版本。
6. 分镜的手部动作、商品朝向、镜头起终状态是跨段衔接依据。“相同人物／完全一致”不能代替这些具体记录。
7. 宫格用于比较和故事预览；提交视频服务的素材按其真实支持的角色整理。宫格不能默认当单张商品图，也不能假定会逐格生成。
8. 五个通用辅助技能全部保留，但按任务需要调用。它们不成为每条视频的强制步骤，也不会因为被调用就自动访问邮箱、日历或私人文档。
9. 多视角模块是同一模型的角色化审查时必须如实说明；多数意见不能当独立模型验证或真实观众数据。
10. 用户只需要翻译、文案或单个功能时，可直接调用对应技能，并补足它所需的最少输入。

## 变更和返修

| 变化／失败 | 回到哪里 | 失效范围 |
|---|---|---|
| 商品事实、目标语言、禁改项变化 | 总导演更新项目记录 | 所有引用旧值的下游产物 |
| 原片听错、切点错 | 拆解／翻译 | 引用对应证据的创意、台词、分镜和提示词 |
| 创意不成立或虚构效果 | 创意／商品适配 | 该方案及其下游 |
| 台词超时 | 台词编写与翻译 | 关联镜头音频、字幕和生成包；不能只加速到不可懂 |
| 关键帧产品变形或遮挡错 | 关键帧模块 | 该素材及其引用段落；通过的图继续复用 |
| 视频动作错误或产品变化 | 对应分段的分镜／提示词／参考图 | 该段和必要的相邻接点 |
| 只有发布文案不合适 | 文案模块 | 文案本身 |

修改保留原版本和原因。未受影响的产物继续复用。输入版本改变后不能复用旧的付费批准或旧验收。

## 本地图片和 H3 的衔接

- 实际开始新视频、相关图像／音频或脚本制作时，按所在项目要求确认技能、路线与模型；本轮已确认的内容继续沿用。工具箱结构审阅不是媒体制作批准。选定方案及分镜自检通过后再生成关键帧。
- 图片使用用户本地已安装的图片模型。本机已有 Qwen-Image-Edit-2511 的工具说明，可作为适配候选；运行时检查服务、队列和所需模型。该模型是图片编辑入口，没有合适底图时先核实输入要求，不假定能无条件纯文生图。
- 视频使用 H3 API。已有本机 `handoff` 复刻入口要求参考原视频；独立原创路线不能伪造原视频或用黑片绕过接口。底层载荷构造允许省略视频，但这不证明服务端当前已验证纯图生视频。执行时单独验证实际 H3 路线与参数；仅有复刻入口时明确报告能力缺口。
- 先检查本地队列与模型能力，不清空或中断其他任务。等待由脚本负责；长提示词和重复轮询不反复放入对话。
- 先做足以判断商品与构图的少量候选图，确认后复用；需要用户看图的节点按本条任务约定执行。
- 新工具箱默认先做一个代表段，审看通过后再扩大到其余段落；用户指定其他已确认路线时按其节点执行。此处默认不改动原项目轻量版的直接生成规则。
- 付费前展示具体批次的服务商、模型、数量、时长、分辨率、价格单位与依据、预计总价、最高预算和上传素材。批准只覆盖该批次与输入版本。
- 提交结果不明时先查询原任务，禁止直接再付费提交。重试范围和预算单列，不能通过“优化”获得无限重试授权。
- 图片通过、视频技术检查通过、内容审看通过、用户接受是四种不同状态。

## 路线预设

- 多参考创作：商品事实 → 各参考证据 → 可借鉴的钩子／展示／收尾 → 一个统一新故事 → 分镜 → 本地图片 → H3 → 审看／回拼 → 文案。
- 原创故事：商品事实 → 创意候选 → 选案 → 分镜 → 本地图片 → H3 → 审看／回拼 → 文案。没有原片时不启动反推。
- 参考裂变：原片证据 → 内容单元规划 → 商品适配 → 生图／视频提示词 → 相同生成验收接口。四套提示词的方法完整保留。
- 精确拆解：逐句证据与逐镜细节，用于确实需要精确对应原片的任务；不强迫普通原创视频填写 43 列。已有项目复刻路线继续按原项目规则执行。


实际执行与配置见 [模型交接](backends.md)。预检命令不会上传或生成媒体。
